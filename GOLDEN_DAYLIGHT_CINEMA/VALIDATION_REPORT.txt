SOURCES (official / cross-checked technical references)
================================================================================

Apple Log 2 / Apple Log transfer function
  - Apple Inc., "Apple Log Profile White Paper" (Sept 2023) and
    "Apple Log 2 White Paper" (Sept 2025): identical curve constants
      R_0 = -0.05641088, R_t = 0.01, c = 47.28711236,
      beta = 0.00964052, gamma = 0.08550479, delta = 0.69336945.
    Apple Log 2 uses the SAME transfer function as Apple Log; only the gamut
    changes. 18% grey encodes to 10-bit code value 500.
  - Cross-checked against colour-science
    `colour.models.log_encoding_AppleLogProfile` and the ACES transform
    `IDT.Apple.AppleLog_BT2020.ctl` (vendorSupplied/apple).
  - Apple developer docs, AVCaptureColorSpace: appleLog = BT.2020 primaries +
    Apple-defined log curve; appleLog2 = "Apple Gamut" primaries + the same
    Apple-defined log curve. https://developer.apple.com/documentation/avfoundation/avcapturecolorspace

Apple Wide Gamut primaries
  - Apple Inc., "Apple Log 2 White Paper" (Sept 2025):
      R (0.725, 0.301), G (0.221, 0.814), B (0.068, -0.076), D65 white.
    The negative blue y places the blue primary outside the spectral locus
    (an "imaginary" primary, as used by ACES / ARRI Wide Gamut).
  - Cross-checked against ASWF OpenColorIO PR #2343 ("Add Apple Log 2
    built-in transform") and OpenColorIO-Config-ACES PR #179 ("Adds Apple
    Log 2 and Linear Apple Wide Gamut"), which derive the AppleWG -> ACES2065-1
    matrix from these primaries with Bradford adaptation.

Output target
  - Rec.709 / BT.709 primaries (R 0.640/0.330, G 0.300/0.600, B 0.150/0.060),
    D65 white, gamma 2.4 OETF (standard SDR video target).

.cube LUT format
  - Adobe, "Cube LUT Specification 1.0": 3D tables stored with the RED index
    changing fastest (index = r + g*N + b*N*N); LUT_3D_SIZE N, DOMAIN_MIN/MAX.
  - Verified against the LUTLINE / rawcut .cube documentation (red-fastest
    ordering confirmed).

Blackmagic Camera (iOS) LUT support / install

================================================================================
SIMULATION OF APPLE LOG 2 (what was used and how)
================================================================================

Genuine Apple Log 2 footage from an iPhone 17 Pro was NOT available in this
environment. The eight source images are PROCEDURALLY GENERATED (value-noise
textures, gradients and vector shapes) -- they are not photographs and not
iPhone sensor captures.

The "Apple Log 2" input used for every BEFORE/AFTER pair is a documented
SIMULATION produced by the exact inverse of the LUT's decode stage:

    sRGB-encoded scene image
      -> decode sRGB to linear Rec.709
      -> convert linear Rec.709 to linear Apple Wide Gamut
         (inverse of the white-preserving AppleWG -> Rec.709 matrix)
      -> encode linear Apple Wide Gamut with Apple's published Apple Log 2
         transfer function.

Because this is the precise inverse of the LUT's decode + gamut stage, it
exercises the real log curve and the real wide-gamut transform. It does NOT
reproduce an iPhone 17 Pro sensor's noise, moire, lens characteristics, or
exact colour response, and it should NOT be taken as representative of real
capture. Source images are included in assets/ (sceneN_*_source.png).

BEFORE = the simulated Apple Log 2 decoded to Rec.709 gamma 2.4 with NO
creative grade (the correct, neutral baseline). AFTER = the delivered
GOLDEN_DAYLIGHT_CINEMA.cube applied to the SAME simulated Apple Log 2 input
(read back from the .cube file and trilinearly interpolated), so the AFTER
images demonstrate exactly what the shipped LUT produces.

================================================================================
LIMITATIONS AND TRADE-OFFS (reported honestly)
================================================================================

1. NO PHYSICAL IPHONE / BLACKMAGIC CAMERA TEST WAS PERFORMED.
   The LUT was validated mathematically and against simulated Apple Log 2.
   Compatibility with Blackmagic Camera on iOS is inferred from official
   .cube support documentation, not confirmed by on-device testing. Install
   and preview on the device before relying on it for a shoot.

2. SIMULATED SOURCE, NOT REAL SENSOR FOOTAGE.
   See the SIMULATION section. Real Apple Log 2 capture includes sensor noise,
   lens characteristics and a colour response that differ from the synthetic
   test images. Behaviour on real footage should be spot-checked.

3. A LUT CANNOT RECOVER CLIPPED HIGHLIGHTS.
   If highlights were clipped (overexposed to flat white) at capture, the log
   curve has already lost the detail and no LUT can restore it. The grade
   rolls off highlights smoothly, but it can only preserve texture that was
   actually captured. Expose to protect highlights in camera.

4. SHADOW BEHAVIOUR.
   Below-black Apple Log 2 values (the log curve's negative offset / sensor
   black level) are clipped to 0, which is correct. The tone curve is smooth
   and monotonic across the real shadow range, so shadow detail is preserved
   (no crushed blacks), but the very deepest blacks sit near black rather than
   being lifted.

5. ACES-ROUTED VS DIRECT CONVERSION.
   Apple's own Apple Log 2 -> Rec.709 LUTs route through the ACES 2.0
   pipeline, which adds the ACES RRT filmic tone-map and a specific chromatic
   adaptation. This LUT instead uses a transparent, white-preserving Apple
   Wide Gamut -> Rec.709 primaries matrix (standard practice for log -> 709
   LUTs) and applies the creative grade on top. Both are "correct" decodes;
   they differ by the ACES look. The difference is quantified in section [3]
   (derived AppleWG->ACES vs the published ASWF matrix: max |diff| 0.3447,
   due to the ACES-specific adaptation).

6. FOLIAGE / GREEN HUE.
   Gamma darkening of greens can lean dark foliage slightly toward green-cyan.
   The hue-aware warmth counteracts this to keep foliage a natural warm green
   (measured ~116 deg), but very dark foliage may retain a subtle cool-green
   lean. It is not radioactive yellow-green and not teal.

7. SKIN.
   Skin is kept natural and subtly warm (measured hue ~27 deg, controlled
   saturation). On already very warm golden-hour light the added warmth is
   gentle; if a specific shot needs cooler skin, adjust white balance/exposure
   in camera or in post. No beauty smoothing is applied -- skin texture is
   preserved.

8. MIDDAY / BRIGHT FOOTAGE.
   The grade darkens and enriches bright footage rather than brightening it,
   and rolls highlights off smoothly. Whites stay believable (measured ~0.85
   lightness for a bright source), and warmth tapers near the top so
   highlights are not forced yellow.

9. 33x33x33 RESOLUTION.
   33^3 with trilinear interpolation is standard and smooth for this look.
   Very fine high-frequency detail is interpolated, which is normal for a
   3D LUT of this size.

10. EXPOSURE TESTING.
    Exposed-simulation tests at 0.7x, 1.0x and 1.4x confirm the LUT stays
    finite and in range across exposure levels; they do not substitute for
    real exposure testing on a camera.
