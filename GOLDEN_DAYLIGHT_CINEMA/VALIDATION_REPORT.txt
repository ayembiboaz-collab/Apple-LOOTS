================================================================================
GOLDEN DAYLIGHT CINEMA  —  VALIDATION REPORT
================================================================================

This report documents the sources, the tests performed, the results, and the
limitations of GOLDEN_DAYLIGHT_CINEMA.cube. Only tests that were actually run are
listed. Nothing here claims physical device testing that did not happen.

--------------------------------------------------------------------------------
1. TECHNICAL SPECIFICATION (verified)
--------------------------------------------------------------------------------
Input : Apple Log 2, Apple Wide Gamut (iPhone 17 Pro, Blackmagic Camera for iOS)
Output: Rec.709 SDR, gamma 2.4
Format: one 33 x 33 x 33 3D .cube LUT (standalone: decode + gamut + grade + encode)

Apple Log 2 transfer function (identical to Apple Log; from Apple's white paper
and reproduced in the ACES CSC):
  Decode:  L = R0                         for V < 0
           L = sqrt(V/c) + R0             for 0 <= V < Pt
           L = 2^((V-delta)/gamma) - beta for V >= Pt
  Constants: R0=-0.05641088, Rt=0.01, c=47.28711236, beta=0.00964052,
             gamma=0.08550479, delta=0.69336945, Pt=c*(Rt-R0)^2

Apple Wide Gamut primaries (Apple Log 2 white paper, Sept 2025), D65 white:
  Red (0.725, 0.301)  Green (0.221, 0.814)  Blue (0.068, -0.076)  White D65

AWG -> Rec.709 linear matrix (derived; both spaces share D65, so no chromatic
adaptation transform is required). Verified: neutral white maps to [1,1,1], and
the derivation method reproduces the standard BT.2020 -> BT.709 linear matrix
exactly.
  [[ 1.70728038, -0.51901992, -0.18826046],
   [-0.12501075,  1.31466236, -0.18965162],
   [-0.04362433, -0.19121437,  1.23483871]]

Output encode: Rec.709 gamma 2.4 (V = L^(1/2.4)) with a smooth highlight
shoulder so speculars roll off instead of clipping.

3. SIMULATION METHOD (because no genuine Apple Log 2 footage was available)
--------------------------------------------------------------------------------
No iPhone 17 Pro sensor footage was available. The before/after previews use
DOCUMENTED SIMULATED Apple Log 2, built as follows:

  1. A Rec.709 gamma-2.4 reference image (generated photographic scene) is treated
     as the correctly-exposed, correctly-graded scene.
  2. It is decoded to linear Rec.709, converted to linear Apple Wide Gamut, and
     encoded with the Apple Log 2 curve -> "simulated Apple Log 2" code values.
  3. The BEFORE preview is those log code values displayed straight through
     Rec.709 gamma 2.4 (the flat, ungraded log appearance).
  4. The AFTER preview is produced by evaluating the DELIVERED
     GOLDEN_DAYLIGHT_CINEMA.cube (parsed and trilinearly interpolated) on those
     exact log values. No separate approximation is used.

The simulation is mathematically faithful to the published curve and gamut: the
neutral path (decode + gamut + gamma 2.4, no creative grade) reproduces the
source Rec.709 image to a mean absolute error of 0.0001-0.0107 (the residual is
33³ trilinear sampling). This confirms the decode, gamut conversion and gamma
encode are correct.

This is NOT iPhone sensor footage. It validates the LUT mathematics and the look,
but does not represent the iPhone 17 Pro sensor's actual colour response, noise,
or highlight behaviour.

Reference scene sources: the eight SOURCES/scene*.png images were generated for
this project (synthetic photographic references). No third-party photographs are
used, so there are no external image licences to honour.

--------------------------------------------------------------------------------
4. TESTS PERFORMED AND RESULTS
--------------------------------------------------------------------------------
All tests were run against the delivered .cube file (parsed + trilinearly
evaluated), not the in-memory function, except where noted.

[1] File, syntax, numerical integrity  — PASS
    LUT_3D_SIZE 33; 35,937 entries (33^3); all values finite; no NaN/Inf;
    value range [0.000000, 1.000000]; all within [0,1].

[2] Neutral behaviour (gray ramp)  — PASS
    Neutral inputs map to near-neutral outputs with only a small warm spread
    (max channel spread 0.022 at mid-high luminance, the intended subtle warmth;
    ~0.000-0.007 elsewhere). No strong overall colour cast.
    18% grey Apple Log 2 code 0.4883 -> output ~0.386 (a sane mid-level).

[3] Highlight roll-off  — PASS
    Gray ramp is monotonic through the highlights and rolls off smoothly:
    log 0.70 -> 0.950, 0.75 -> 0.959, and flat 0.959 for 0.80-1.00 (soft
    saturation, no hard clip). Maximum non-monotonic "wiggle" across the full
    gray ramp is 0.0054 (negligible).

[4] Exposure invariance (simulated +1, 0, -1 stop)  — PASS
    Applied to three scenes at three exposures. No clipping at any level
    (clipped_frac = 0.0000 in all cases). Shadows stay deep (p1 ~0.04-0.06) and
    highlights stay controlled (p99 <= 0.959) across exposures.

[5] Skin / sky / foliage behaviour (delivered cube)  — PASS (targets met)
    Sky    : hue 194-205 deg (natural blue), controlled saturation, no turquoise.
    Foliage: hue 60-116 deg (green preserved), controlled saturation, no
             yellow-green / radioactive shift.
    Skin   : hue 30-37 deg (natural, subtly warm), saturation increase only
             ~+0.02-0.06 vs source (not orange, not oversaturated).

[6] Interpolation fidelity (in-memory grade vs delivered cube)  — PASS
    Mean absolute error 0.0038-0.0083 across the eight scenes (max 0.0083).
    This is the expected 33³ trilinear sampling error.

[7] AFTER renders from the delivered .cube  — PASS
    All eight AFTER previews were produced by evaluating the delivered
    GOLDEN_DAYLIGHT_CINEMA.cube (CubeLUT, trilinear) on the simulated Apple Log 2
    values — not a separate approximation.

[8] Gallery  — TESTED AS FAR AS THE ENVIRONMENT PERMITS
    The gallery (GALLERY/index.html) was served over HTTP and verified: the page,
    all 16 preview images, the contact sheet and the .cube link all return HTTP
    200. The interactive slider and fullscreen code uses standard pointer events
    (mouse + touch). No physical iPhone/Safari test was performed.

--------------------------------------------------------------------------------
5. LIMITATIONS (honest)
--------------------------------------------------------------------------------
1. SIMULATED FOOTAGE. The previews use simulated Apple Log 2, not iPhone 17 Pro
   sensor footage. The LUT maths is validated, but the exact appearance on real
   Apple Log 2 captures (sensor colour, noise, highlight clipping behaviour) is
   not verified here.

2. NO PHYSICAL DEVICE TESTING. The LUT was not loaded into a physical iPhone or
   Blackmagic Camera. Gallery serving was tested over HTTP only. Device
   compatibility is inferred from Apple/Blackmagic documentation, not tested.

3. 33³ TRILINEAR INTERPOLATION. A 33³ LUT is a sampled approximation of the
   grade. Interpolation error is small (max 0.0083 MAE) but present. It is most
   visible in very dark, very saturated regions (e.g. deep-shadow foliage
   saturation reads lower through the cube than the ideal function, because the
   saturation metric amplifies small absolute errors on small values). A 65³ LUT
   would reduce this if a desktop tool supports it, but 33³ was the required
   format.

4. A LUT CANNOT RECOVER CLIPPED HIGHLIGHTS. If the Apple Log 2 capture clipped a
   highlight, no LUT can restore the lost detail. Expose to protect highlights
   in camera.

5. HIGHLIGHT SATURATION. The soft highlight roll-off saturates near 0.959 code
   (not 1.0). Very bright speculars will settle just below full white by design;
   this is intentional to avoid harsh clipping, but it means "pure white" is
   approached asymptotically.

6. PARAMETER TUNING WITHOUT DISPLAY INSPECTION. The grade parameters were tuned
   against numerical targets (hue/saturation/luminance statistics) rather than by
   looking at a calibrated display. The look is designed to hit the stated
   targets, but final subjective evaluation on real footage is recommended; minor
   adjustment of warmth/contrast may be desired for a specific camera or scene.

7. APPLE WIDE GAMUT SENSOR MATCHING. Apple publishes the log curve and AWG
   primaries but not the per-sensor native response. Exact colour matching to a
   real iPhone 17 Pro capture is therefore not guaranteed; the conversion is
   correct for the published specification.

8. GALLERY DOWNLOAD IN EMBEDDED PREVIEW. If an embedded/iframe preview blocks
   downloads, use the direct GitHub links to the .cube and .zip instead. The
   gallery was verified by direct HTTP serving, not inside an embedded iframe.

--------------------------------------------------------------------------------
6. WHAT WAS SIMULATED vs TESTED vs NOT TESTED
--------------------------------------------------------------------------------

            roll-off, exposure invariance, skin/sky/foliage behaviour,
